# GEO single-cell loader

Use the directory containing `.agents/skills/geo-single-cell-loader` as repository root. Run all commands from that root. A request such as “下载单细胞数据 GSE231993”, “下载 GSE231993”, “处理 GSE231993”, “读取 GSE231993”, “分析单细胞数据 GSE231993”, “帮我下载并整理 GSE229413”, or “Download and prepare GSE231993” starts the complete workflow below. Users do not need `$geo-single-cell-loader`, stage names, or manual Python/R commands. Execute those details yourself. “分析” here prepares the object; do not add downstream analysis.

Keep one self-contained directory per study. After a terminal run and successful audit push, `data/<GSE>/` contains only `raw/`, `seurat_raw.rds` when built, `sample_info.txt`, `group_confirmation.json` when confirmed, and `cell_map/` only when required to reconstruct the object. `raw/` means downloaded source expression files unchanged by this Skill, not necessarily sequencing FASTQ raw reads. `.workflow/` is temporary across Stage A, group confirmation, download, build and audit upload; remove it only after the audit push succeeds. Use system temporary directories for conversions and clean them at the end. Never put runtime data inside the Skill or create root datasets/manifests/logs/output folders. Read [audit-policy.md](references/audit-policy.md) before every real GSE run.

## Stage A — inspect and report

These stage names are internal. Describe the next action naturally to the user.

Start each real run with `audit_run.py start GSE...`. Capture objective file decisions in temporary `.workflow/file_selection_reasons.csv` (`url,reason`) and `.workflow/decision_notes.md`; explain each excluded expression candidate. If discovery fails or the run is interrupted, call `audit_run.py finalize GSE... --status failure|interrupted --reason "..." ` so the partial audit is pushed. A workflow waiting for the user's grouping is still active and is finalized after Stage B.

1. **EVERY new Stage A discovery MUST first actually attempt the user-level global `geo` MCP.** For a known `GSE\d+`, call `get_geo_info(GSE)` and then `list_geo_files(GSE)`; call `get_geo_sample(GSM)` only for specific missing GSM detail, never unconditionally for the complete inventory. For a keyword, call `search_geo(query)`, select a candidate, then call `get_geo_info(selected_GSE)` and `list_geo_files(selected_GSE)`. Do not run `inspect_geo.py` first and do not claim MCP is unavailable merely because it has not yet been called or is absent from an old session's visible tool list.
2. **Validate MCP completion.** `get_geo_info` must return the requested accession, `complete=true`, `sample_count`, exactly that many unique GSM records, and source URLs. `list_geo_files` must return files with explicit `owner_accession`, `source_level`, and `candidate_format`. Supplement missing details through MCP when possible. If both calls succeed, use only their structured public facts for Stage A artifacts and do not rerun `inspect_geo.py` “for insurance.” If a real call is unavailable, startup fails, a tool/NCBI request ultimately errors, or MCP remains irreparably incomplete, record the concrete reason and only then use `inspect_geo.py --fallback-reason "..."`. An old session must first verify `codex mcp get geo`, open a fresh session in this repository, and retry the real tools before recording `CURRENT_SESSION_MCP_UNAVAILABLE`.
3. **Do not bulk-download before presenting sample information.** Read Series, every relevant GSM, associated publications and publicly linked supplementary sample/clinical metadata. The fallback script fetches metadata and abstracts, not all publication supplements: follow those links yourself. Its format labels are candidates until contents are verified. A development `--max-samples` report is incomplete and cannot represent all samples.
   Apply the single-cell modality gate to the structured Stage A facts. Explicit microarray or bulk RNA-seq evidence stops the single-cell workflow before expression download and Seurat construction. An unresolved modality also cannot enter the confirmed builder. Only an explicit user request to download files despite the non-single-cell modality permits an ordinary file download, never a Seurat build.
4. Stage A writes `.workflow/inspection.json`, `.workflow/sample_report.csv` and UTF-8 plain `sample_info.txt`, initially `STATUS: WAITING_FOR_GROUP_CONFIRMATION`. `inspection.json` records `gse`, `series`, `samples`, `files`, `input_plans`, publication facts, `total_samples`, `inspected_samples`, `complete`, `source`, `discovery_method`, `mcp_tools_used`, `mcp_complete`, `discovery_started_at`, `discovery_finished_at`, and `discovery_seconds`; `fallback_reason` exists only for fallback. MCP success uses `source="global geo MCP"` and `discovery_method="geo_mcp"`; fallback uses `discovery_method="inspect_geo_fallback"`. Enrich the sample report using public evidence. Show every sample's `sample`, `author_sample`, `tissue`, `disease`, `source_type`, `sample_description`; optional fields only when reliably mapped. Record sequencing modality, study context, raw/filtered availability, separate clinical/cell metadata, and unresolved facts. Refresh the TXT with `sample_info.py GSE...` after evidence review. Do not silently invent values to fill blank fields. Development probes are isolated in `.workflow/development/` and cannot serve as complete reports.
5. If an existing `.workflow/` belongs to the same unfinished confirmed workflow, preserve its group confirmation, manifest hash, download provenance, raw files, and final RDS. MCP may perform a read-only refresh/verification, but must not silently rebuild the confirmed workflow. A user-explicit new Stage A discovery is still MCP-first.
6. **group must always be confirmed by the user.** Say: **group 尚未创建，请确认分组方式。** Show facts before asking. A request to “download and read GSE229413” still starts here. Never infer group from disease or filenames. PDAC uninvolved pancreas still has disease PDAC, not Healthy.

## Stage B — explicit grouping, download, create

Read [metadata-schema.md](references/metadata-schema.md) before building the manifest and [format-routing.md](references/format-routing.md) for the selected format.

Complete steps 1–3 to record the user's group and validate the manifest. Then use `run_confirmed.py GSE...` for download, the lightweight pre-build probes, dependency checks, build, validation and automatic audit push; do not run those later commands separately for a real GSE. Read [prebuild-probes.md](references/prebuild-probes.md) for pending text fields and pooled mapping evidence. The runner removes `.workflow/` only after push succeeds. Save the confirmed group JSON at the dataset root through audit finalization. Keep necessary cell maps in `data/<GSE>/cell_map/` (legacy temporary `.workflow/` maps are copied there before cleanup).

1. After the user's reply, expand their rules into an exact `sample -> group` JSON map. Preserve their literal statement and `confirmed_by: user`. When the user explicitly selects only some samples, keep the complete Stage A report and add `selected_samples` to the confirmation; its keys and the group map must exactly match the selected manifest rows. Without an explicit subset, cover all sample keys. This records user intent; it is not an authentication system. Never synthesize a user statement or fill unconfirmed groups. Synthetic fixtures use explicitly labeled simulated approval and never clinical conclusions.
2. Resolve all required biology and file mapping facts. Adopt `input_plans` only after evidence review. Canonical trio names can be proposed from GSM-owned links; patient/specimen identities cannot. Prefer filtered over raw **within one evidenced sample**. For pooled matrices without an explicit map, inspect internal barcode/library IDs, GEO supplementary metadata, linked publication supplements, and the author's public repository in that order; record each source check in `.workflow/mapping_evidence.json`. Continue only with a publicly sourced exhaustive cell-to-sample map. If barcode suffix groups and GSM counts differ, stop; never pair suffixes with GSMs by order.
   When several files may represent the same raw counts, first record one evidenced `raw_counts_id` and `same_counts_evidence` for each equivalent candidate. Use `select_verified_raw_counts()` from `scripts/common.py` with a content-validation callback and `.workflow/candidate_probe.json` as `audit_path`. The selector prefers verified sparse RDS/H5/MTX, then a dense RDS whose loaded object uses at most 25% of total physical RAM, then streaming TXT. Give a previously validated TXT `verified_raw_counts=true` and `verification_evidence`; unknown remote binary is skipped when this route is usable. Probe binary first only when it already exists locally, public evidence explicitly identifies sparse/native raw counts, or no usable raw-count route exists. A previously inspected local binary may supply `validated_evidence` with `structure_evidence` to avoid rereading it. Base dense memory risk on `object.size()` after `readRDS()`, never compressed `.rds.gz` bytes. Never select normalized/log/SCT/scaled data. Build the manifest for the validated choice without changing a confirmed receipt in place.
3. Save `.workflow/group_confirmation.json`. Build `.workflow/sample_manifest.csv` with `build_manifest.py --report data/<GSE>/.workflow/sample_report.csv --confirmation data/<GSE>/.workflow/group_confirmation.json --output data/<GSE>/.workflow/sample_manifest.csv`. It writes `sample_manifest.confirmation.json` and refreshes `sample_info.txt` with confirmed group fields and GROUP SUMMARY. **Use manifest as the source of truth.** Manual edits require reconfirmation. The pre-build probe may fill only verified blank technical fields (delimiter, orientation, feature ID, text reader/memory evidence, 10x feature fallback, cell map) and refresh the receipt without changing user-confirmed samples or groups. Run `--validate` before downloading. Do not bypass these checks by manually writing receipt hashes. Keep old receipts unchanged when archiving or migrating; never bless a path edit automatically.
4. The runner calls `download_processed.py data/<GSE>/.workflow/sample_manifest.csv`. It retries transient timeout, connection reset and HTTP 408/429/5xx failures at most three times with 2/5/10-second backoff, records actual retries, and never treats `.part` as complete. Sources go to `raw/`; URL, UTC timestamp, bytes and SHA256 go to `.workflow/download.json`, persisted per file for resumability. Existing files and extracted archive members must match URL/member, size and checksum provenance before reuse; mismatches stop without overwriting. Small public sample metadata may be fetched during Stage A; bulk count matrices may not. For archives, specify exact members and canonical destinations in manifest; no broad extraction. Inspect unfamiliar input contents and counts provenance; a filename or integer-looking matrix alone does not prove raw counts. If mapping changes, return to confirmation.
5. Check dependencies using `Rscript scripts/check_dependencies.R` (use the actual script path). Use a verified R installation with Seurat; optional missing format packages should stop only the affected route. Prefer `zellkonverter` native R for H5AD. If it is unavailable and a prevalidated Python with `anndata/numpy/scipy` exists, set `GEO_SINGLE_CELL_PYTHON` explicitly for the fallback. Never silently create or install a Python/Conda environment during conversion.
6. Stage B uses one explicit pipeline: `route_input()` selects the verified route, `read_expression()` returns the unified raw sparse-count contract, and `map_input_cells()` independently creates cell/sample identity. Group manifest rows by a read signature containing every reader-affecting field, including `local_path`, `file_type`, `count_source`, `delimiter`, `orientation`, `feature_column`, `drop_columns`, `assay`, and `layer`. Each unique signature is held in the build-local `loaded_inputs` cache and read at most once. Rows that share a path but disagree on reader configuration stop with `Shared input has inconsistent reader configuration across manifest rows.` A one-sample input without a cell map keeps the ordinary prefix-and-map behavior.
7. A shared/pooled input must have one consistent exhaustive `cell_map_path`. Read the pooled matrix once and the shared cell map once; require nonblank unique `cell`, nonblank `sample`, exact matrix-cell equality, and exact manifest-sample equality. Map cells in matrix order, rename once with `sample_cell`, and keep the pooled sparse matrix intact. Never reread it once per sample, split it into sample matrices, or reconstruct it by cbind. Multiple pooled/independent physical inputs are supported and combined only after each has been prepared once.
8. Require identical feature sets across prepared inputs; reorder safely when only feature order differs, and stop with `Feature sets differ between samples; explicit reconciliation is required.` when sets differ. Combine all sparse count matrices before one `CreateSeuratObject(min.cells=3,min.features=200)` call, so `min.cells` is evaluated across the entire GSE. Release the prepared counts/alignment lists immediately after combination and the standalone merged matrix immediately after construction metrics, calling `gc()` at both boundaries. Map final retained Cells back to samples by cell key, set `orig.ident=sample`, then apply manifest metadata. Do not create one Seurat object per sample or use Seurat merge/JoinLayers for initial construction.
9. Run `Rscript .agents/skills/geo-single-cell-loader/scripts/build_seurat.R . data/<GSE>/.workflow/sample_manifest.csv`, then the independent `validate_seurat.R . data/<GSE>/.workflow/sample_manifest.csv data/<GSE>/seurat_raw.rds`. The builder saves `.workflow/run_summary.txt`, including manifest rows, unique signatures, actual expression/cell-map reads, per-input dimensions and reader, and per-stage timings. Validation requires one raw RNA counts layer and rejects author/downstream reductions, SCT/integrated assays, graphs and neighbors. `sample_info.txt` becomes `STATUS: COMPLETE` only after serialized validation and RDS finalization. Build errors set `STATUS: BUILD_FAILED` with a concise reason when the dataset directory exists; retain verified raw files. If independent validation fails, use `sample_info.R::update_sample_info` to record BUILD_FAILED and report the cause. Never overwrite an existing final RDS silently.

**database/sample/tissue/disease/source_type/group are required in final Seurat objects. patient/specimen/cohort/treatment are optional and must never be guessed.** GSM is preferred; use documented author sample IDs only when a GSM is not one matrix sample. Source names and descriptions remain available for traceability.

**Never silently continue after sample mapping ambiguity.** Reject missing, duplicate, unmatched or anomalous mappings. Prefix barcodes before sparse matrix combination. Assign metadata by stable cell keys after `min.features` filters cells; verify cell alignment, `orig.ident=sample`, retained sample sets and a single RNA counts layer. Empty samples stop the run. No final RDS is written until in-memory and serialized validation succeed.

**Stop after creation of seurat_raw.rds; do not run downstream scRNA-seq analysis.** The explicitly requested `CreateSeuratObject(min.cells=3, min.features=200)` construction thresholds are recorded; perform no additional QC, normalization, scaling, PCA/UMAP, clustering, doublet detection, annotation, differential expression or enrichment. Never call NormalizeData, SCTransform, FindVariableFeatures, ScaleData, RunPCA, RunUMAP, FindNeighbors, FindClusters or DoubletFinder.

Report outputs, sample/group cell counts, count source, warnings and limitations. FASTQ/SRA-only datasets: “该数据没有可直接读取的processed expression matrix。需要FASTQ/SRA重新定量，超出当前V1范围。” Do not run Cell Ranger.

See [test-datasets.md](references/test-datasets.md) for real discovery cases and synthetic regression tests; development authorization does not assign real biological groups.
