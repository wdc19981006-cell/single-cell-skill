# GEO single-cell loader

Use the directory containing `.agents/skills/geo-single-cell-loader` as repository root. Run all commands from that root. A request such as “下载单细胞数据 GSE231993”, “下载 GSE231993”, “处理 GSE231993”, “读取 GSE231993”, “分析单细胞数据 GSE231993”, “帮我下载并整理 GSE229413”, or “Download and prepare GSE231993” starts the complete workflow below. Users do not need `$geo-single-cell-loader`, stage names, or manual Python/R commands. Execute those details yourself. “分析” here prepares the object; do not add downstream analysis.

Keep one self-contained directory per study: `data/<GSE>/raw/`, `data/<GSE>/seurat_raw.rds`, `data/<GSE>/sample_info.txt`, and `data/<GSE>/.workflow/`. `raw/` means downloaded source expression files unchanged by this Skill, not necessarily sequencing FASTQ raw reads. All inspection, report, manifest, confirmation, download provenance, cell maps and run summaries belong in `.workflow/`. Use system temporary directories for conversions and clean them at the end. Never put runtime data inside the Skill or create root datasets/manifests/logs/output folders.

## Stage A — inspect and report

These stage names are internal. Describe the next action naturally to the user.

1. **Search first.** Prefer available bio-server MCP `search_geo` and `get_geo_info`. If unavailable, use `scripts/inspect_geo.py GSE...`; keyword search uses `--search`. Do not assume an unavailable MCP server exists.
2. **Do not bulk-download before presenting sample information.** Read Series, every relevant GSM, associated publications and publicly linked supplementary sample/clinical metadata. The script fetches metadata and abstracts, not all publication supplements: follow those links yourself. Its format labels are candidates until contents are verified. A development `--max-samples` report is incomplete and cannot represent all samples.
3. `inspect_geo.py GSE...` writes `.workflow/inspection.json`, `.workflow/sample_report.csv` and UTF-8 plain `sample_info.txt`, initially `STATUS: WAITING_FOR_GROUP_CONFIRMATION`. Enrich the generated sample report using public evidence. Show every sample's `sample`, `author_sample`, `tissue`, `disease`, `source_type`, `sample_description`; optional fields only when reliably mapped. Record sequencing modality in inspection's `sequencing_type`, study context, raw/filtered availability, separate clinical/cell metadata, and unresolved facts. Refresh the TXT with `sample_info.py GSE...` after evidence review. Do not silently invent values to fill blank fields. Development probes are isolated in `.workflow/development/` and cannot serve as complete reports.
4. **group must always be confirmed by the user.** Say: **group 尚未创建，请确认分组方式。** Show facts before asking. A request to “download and read GSE229413” still starts here. Never infer group from disease or filenames. PDAC uninvolved pancreas still has disease PDAC, not Healthy.

## Stage B — explicit grouping, download, create

Read [metadata-schema.md](references/metadata-schema.md) before building the manifest and [format-routing.md](references/format-routing.md) for the selected format.

1. After the user's reply, expand their rules into an exact `sample -> group` JSON map. Preserve their literal statement, `confirmed_by: user`, and all sample keys. This records user intent; it is not an authentication system. Never synthesize a user statement or fill unconfirmed groups. Synthetic fixtures use explicitly labeled simulated approval and never clinical conclusions.
2. Resolve all required biology and file mapping facts. Adopt `input_plans` only after evidence review. Canonical trio names can be proposed from GSM-owned links; patient/specimen identities cannot. Prefer filtered over raw **within one evidenced sample**. For pooled matrices use an exhaustive explicit cell-to-sample map and record its provenance. Stop on unresolved mapping.
3. Save `.workflow/group_confirmation.json`. Build `.workflow/sample_manifest.csv` with `build_manifest.py --report data/<GSE>/.workflow/sample_report.csv --confirmation data/<GSE>/.workflow/group_confirmation.json --output data/<GSE>/.workflow/sample_manifest.csv`. It writes `sample_manifest.confirmation.json` and refreshes `sample_info.txt` with confirmed group fields and GROUP SUMMARY. **Use manifest as the source of truth.** Exact confirmation receipts bind to manifest contents; edits require reconfirmation. Run `--validate` before downloading. Do not bypass these checks by manually writing receipt hashes. Keep old receipts unchanged when archiving or migrating; never bless a path edit automatically.
4. Run `download_processed.py data/<GSE>/.workflow/sample_manifest.csv`. Sources go to `raw/`; URL, UTC timestamp, bytes and SHA256 go to `.workflow/download.json`, persisted per file for resumability. Existing files and extracted archive members must match URL/member, size and checksum provenance before reuse; mismatches stop without overwriting. Small public sample metadata may be fetched during Stage A; bulk count matrices may not. For archives, specify exact members and canonical destinations in manifest; no broad extraction. Inspect unfamiliar input contents and counts provenance; a filename or integer-looking matrix alone does not prove raw counts. If mapping changes, return to confirmation.
5. Check dependencies using `Rscript scripts/check_dependencies.R` (use the actual script path). Use a verified R installation with Seurat; optional missing format packages should stop only the affected route. Prefer `zellkonverter` native R for H5AD. If it is unavailable and a prevalidated Python with `anndata/numpy/scipy` exists, set `GEO_SINGLE_CELL_PYTHON` explicitly for the fallback. Never silently create or install a Python/Conda environment during conversion.
6. Read each sample with the existing `read_counts()` route, prefix its barcodes, and build an explicit cell-to-sample key map. Require identical feature sets across samples; reorder safely when only feature order differs, and stop with `Feature sets differ between samples; explicit reconciliation is required.` when sets differ. Combine all sparse count matrices before one `CreateSeuratObject(min.cells=3,min.features=200)` call, so `min.cells` is evaluated across the entire GSE. Map final retained Cells back to samples by cell key, set `orig.ident=sample`, then apply manifest metadata. Do not create one Seurat object per sample or use Seurat merge/JoinLayers for initial construction.
7. Run `Rscript .agents/skills/geo-single-cell-loader/scripts/build_seurat.R . data/<GSE>/.workflow/sample_manifest.csv`, then the independent `validate_seurat.R . data/<GSE>/.workflow/sample_manifest.csv data/<GSE>/seurat_raw.rds`. The builder saves `.workflow/run_summary.txt` and sets `sample_info.txt` to `STATUS: COMPLETE` only after serialized validation and RDS finalization, including the construction strategy, sample/group cell counts, total genes/cells, formats, counts source, thresholds, Seurat version, timestamp and warnings. Build errors set `STATUS: BUILD_FAILED` with a concise reason when the dataset directory exists; retain verified raw files. If independent validation fails, use `sample_info.R::update_sample_info` to record BUILD_FAILED and report the cause. Never overwrite an existing final RDS silently.

**database/sample/tissue/disease/source_type/group are required in final Seurat objects. patient/specimen/cohort/treatment are optional and must never be guessed.** GSM is preferred; use documented author sample IDs only when a GSM is not one matrix sample. Source names and descriptions remain available for traceability.

**Never silently continue after sample mapping ambiguity.** Reject missing, duplicate, unmatched or anomalous mappings. Prefix barcodes before sparse matrix combination. Assign metadata by stable cell keys after `min.features` filters cells; verify cell alignment, `orig.ident=sample`, retained sample sets and a single RNA counts layer. Empty samples stop the run. No final RDS is written until in-memory and serialized validation succeed.

**Stop after creation of seurat_raw.rds; do not run downstream scRNA-seq analysis.** The explicitly requested `CreateSeuratObject(min.cells=3, min.features=200)` construction thresholds are recorded; perform no additional QC, normalization, scaling, PCA/UMAP, clustering, doublet detection, annotation, differential expression or enrichment. Never call NormalizeData, SCTransform, FindVariableFeatures, ScaleData, RunPCA, RunUMAP, FindNeighbors, FindClusters or DoubletFinder.

Report outputs, sample/group cell counts, count source, warnings and limitations. FASTQ/SRA-only datasets: “该数据没有可直接读取的processed expression matrix。需要FASTQ/SRA重新定量，超出当前V1范围。” Do not run Cell Ranger.

See [test-datasets.md](references/test-datasets.md) for real discovery cases and synthetic regression tests; development authorization does not assign real biological groups.
