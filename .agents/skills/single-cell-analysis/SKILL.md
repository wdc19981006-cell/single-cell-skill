# Formal single-cell analysis

Storage: read dataset `storage_summary.json` before stage summaries. New baseline temporary RDS/recovery state live in `.work/checkpoints/analysis/baseline/`; `--run-id ID` uses `.work/checkpoints/analysis/runs/ID/`. Formal `03_analysis[/runs/ID]/seurat_analysis.rds`, stage reports and literal decisions remain permanent. Default compact keeps review objects until user resolution plus independent final readback/API checks, then safely cleans this run's intermediates and regression candidate RDS. Config/ARI/transitions/markers/plots/conclusions remain. Use `--storage-mode full` or repeated `--retain-checkpoint STAGE_OR_BASENAME` for intentional retention. INCOMPLETE checkpoints survive failures. Stage result paths describe historical publications; registry/manifests distinguish COMPLETE_RETAINED and COMPLETE_CLEANED. Explicitly requesting a cleaned step reconstructs prerequisites from the recorded QC reference in an isolated rebuild run, recorded in `last_rebuild_result.json`, preserving the original final. Never open every large RDS to decide deletions. Old unregistered results, including GSE149614, are inventory-only; user confirmation is required for any separate cleanup. See [storage protocol](../../../runtime/STORAGE.md); this contract supersedes historical stage-local checkpoint paths below.

Work from the repository root. Use fixed scripts through `analysis/run_workflow.py DATASET [--output-root ROOT] [--run-id ID]`. Input defaults to completed canonical QC-3/QC-2; `--input PATH` supports an existing QC object. Never restart downloads/QC from an analysis-only request. All R executes through `runtime/r45/run_r45.py` in existing R 4.5.0. Do not change packages or the environment.

Configuration is `analysis/default_config.json`, optionally overridden with `--config JSON`. Output defaults to `D:/Desktop/codex-result/single-cell-skill/<DATASET>/03_analysis/` from `runtime/output_config.json`. `--output-root` is the collection root; append DATASET only once. Safe non-GEO names are accepted. `--root OLD_WORKSPACE` explicitly retains the legacy results layout; `--input` reads old objects without moving them. Alternative analyses require a new `--run-id` (under `03_analysis/runs/ID`); never discover another run’s checkpoints. Validate checkpoint/config/input provenance before reuse; never overwrite valid RDS files.

1. `--step pca` freshly runs NormalizeData, FindVariableFeatures, ScaleData with baseline `vars.to.regress="pMT"`, and RunPCA. Never reuse DoubletFinder PCA. decontX is default; missing/invalid corrected counts stop analysis with no RNA fallback. Preserve original RNA and QC metadata; fractional counts stay fractional. Read PC selection, elbow, regressions and warnings in `01_pca_regression/`.
2. Baseline is pMT only. After clustering, `--step regression-review` (included in all) automatically runs only risky feature/count comparisons. Each fixes QC input hash, cells, assay, HVGs, seed, PC count, Harmony design and an actually scanned comparison resolution, and includes downstream clustering, ARI, transitions, markers and sample/group/phase evidence. Cycle risk first requires proliferation Marker review; do not invent `cell_cycle_review` user consent. Read `01_pca_regression/regression_sensitivity/regression_review_result.json`. Recommendations are diagnostic advice; candidates never overwrite baseline. Adoption needs a new run ID and `--regression-decision` with user statement and the matching comparison_config path; re-evaluate PCs and resolution. See [configuration and commands](../../../analysis/README.md) only when configuring a targeted review.
3. `--step harmony` defaults to sample (`enabled=true,batch_field=sample,allow_sample=true`). Do not ask for this field again or fabricate a per-run user confirmation. Valid explicit technical overrides are supported; group is forbidden. Missing/blank/one-level batch fields produce an explicit skip. Sample/group confounding records limitations without reapproval; fully confounded biology cannot be claimed separable by Harmony. Keep unintegrated UMAP and report limitations. Read batch design, mixing metrics, marker comparisons and warnings in `02_harmony/`; mixing alone does not validate integration.
4. `--step cluster-review` scans resolutions on the selected representation and one UMAP. Review `03_clustering/cluster_resolution_review.pdf`, `clustree.pdf`, cell distributions, stability and regression/cluster associations. Ask the user to choose final resolution from the evidence. Never select solely from UMAP or a fixed default.
5. `--step finalize --resolution-decision JSON` requires `confirmed_by="user"`, literal `user_statement`, and a resolution in the actual review. If regression review reports a material tradeoff, the decision also records regression_scheme=baseline and the literal regression_statement to keep this run; choosing a candidate starts a new run. Only then save `seurat_analysis.rds`, formal labels and selected-resolution marker/QC/cycle/sample/group plots. These plots do not constitute cell-type annotation. `--step all` stops at review without a selection. Simulated selections belong only to explicitly marked regression fixtures.

Run `workflow_audit/run_audit.py DATASET [--output-root ROOT] [--run-id ID]` to summarize existing evidence into `03_analysis/99_workflow_audit/`. It does not rerun expression analysis. Missing evidence/failures remain explicit; updated reports are versioned. This scientific report differs from the private ten-file download audit.

Fix technical failures with evidence/tests. Uncertain parameter effects need limited comparisons. Biological tradeoffs require the user's decision: never delete samples/cell populations or erase biological structure on the user's behalf. Report actual RDS/CSV/plot validation and limitations; a skipped method is not a successful computation.

Routine mode: invoke fixed scripts, read only the stage result JSON/audit_summary.json, preserve saved decisions, and ask only for actual unresolved choices. Targeted review mode: run the matching fixed diagnostic only. Development mode applies to an explicit code/Skill change or unresolvable concrete error; run affected regressions, not every test or a whole study. Never rewrite computation per new dataset.
